# Eli Check — benefits check for Maastricht and the Netherlands

**[eli-check.nl](https://eli-check.nl)** · "Eli" is short for eligibility.

Eli Check helps students in Maastricht, and anyone on a low income in the Netherlands, see which allowances,
student finance and local support they are probably entitled to. It asks a few simple questions,
calculates with the official 2026 rules and links to the official websites to apply.
It is a helper, not a decision: people always apply and verify with the paying organisation.

The rules engine is an [OpenFisca](https://openfisca.org) country package (`openfisca_nl`), served through the
standard OpenFisca Web API. The questionnaire in `web/` calls that API.

## What it calculates (2026 rules)

| Scheme | Who decides | Main variable(s) |
|---|---|---|
| Zorgtoeslag (healthcare allowance) | Dienst Toeslagen | `zorgtoeslag` |
| Huurtoeslag (rent allowance — new system since 1 Jan 2026) | Dienst Toeslagen | `huurtoeslag` |
| Kindgebonden budget (child-related allowance) | Dienst Toeslagen | `kindgebonden_budget` |
| Kinderbijslag (child benefit) | SVB | `kinderbijslag` |
| Studiefinanciering: basisbeurs, aanvullende beurs, loan, tuition loan, reisproduct — incl. EU students who work in NL | DUO | `basisbeurs`, `aanvullende_beurs`, `maximale_lening`, `collegegeldkrediet`, `studentenreisproduct` |
| Tegemoetkoming scholieren (secondary school, 18+) | DUO | `tegemoetkoming_scholieren` |
| Bijstand (social assistance) — indication | Gemeente | `bijstand` |
| Income tax and refund for side jobs (2025 and 2026) | Belastingdienst | `inkomstenbelasting`, `belastingteruggave` |
| Maastricht: individuele inkomenstoeslag, studietoeslag, VGZ collective insurance, kwijtschelding (BsGW), child schemes, Volwassenenfonds, bijzondere bijstand — indicators | Gemeente Maastricht / SZMH | `maastricht_*` |

Every scheme also has `<scheme>_voorwaarde_<condition>` booleans (True = condition met), so the UI can explain
*why* someone does or doesn't qualify. The full list of inputs and outputs, with entity and period, is in
[`docs/api.md`](docs/api.md) (generated by `scripts/generate_api_doc.py`).

## Where the numbers come from

Every amount was researched from official sources (Belastingdienst calculation sheets, wetten.overheid.nl,
DUO, SVB, Gemeenteblad Maastricht, SZMH, BsGW, Maastricht University). The notes, with a source and a
VERIFIED / DERIVED / UNVERIFIED label per value, are in [`docs/research/`](docs/research/):

- [`toeslagen-2026.md`](docs/research/toeslagen-2026.md) — zorgtoeslag, huurtoeslag, kindgebonden budget, bijstand norms
- [`studiefinanciering-2026.md`](docs/research/studiefinanciering-2026.md) — DUO amounts, aanvullende beurs formula, EU students
- [`maastricht-tax-2026.md`](docs/research/maastricht-tax-2026.md) — Maastricht schemes, income tax, UM/Zuyd funds, housing help

Each parameter YAML file links to the document it comes from. Rule changes that commonly trip people up:

- **Huurtoeslag 2026**: fixed basishuur plus an income correction; rent above €932.93 is capped instead of
  disqualifying; only the bare rent counts (no service costs); the youth cap applies under 21 (was 23);
  student rooms without their own front door, kitchen, toilet and shower get nothing.
- **EU students**: DUO presumes migrant-worker status from **32 hours a month** (or more than 24 hours for
  6+ months, or €700.75 net a month) — the old 56-hour rule was struck down in 2023.
- **Maastricht IIT** excludes anyone who studied with student finance in the past 36 months.
- **Kwijtschelding** counts the maximum student loan as income for students, so most students are refused.

## Tests

The YAML tests in `openfisca_nl/tests/` reproduce the official worked examples of the Belastingdienst
calculation sheets, DUO's 2026 aanvullende beurs formula, the 2025/2026 tax tables and the Maastricht rules.

```bash
.venv/Scripts/openfisca test openfisca_nl/tests --country-package openfisca_nl
```

## Run it locally

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -e .        # Windows; use .venv/bin/python on macOS/Linux
.venv/Scripts/python server.py                  # http://127.0.0.1:5000
```

`server.py` serves the questionnaire at `/` and the OpenFisca Web API at `/api`
(`POST /api/calculate`, `GET /api/variables`, `GET /api/variable/<name>`, `GET /api/spec`). Set `PORT` to change
the port. Restart it after changing rules: OpenFisca loads them once at start-up.

To put it online (Docker image, Render config, connecting eli-check.nl) see [DEPLOY.md](DEPLOY.md).

## Example API call

```bash
curl -X POST http://127.0.0.1:5000/api/calculate -H "Content-Type: application/json" -d '{
  "personen": {"ik": {
    "leeftijd": {"2026-10": 21}, "onderwijs": {"2026-10": "wo"}, "nationaliteit": {"ETERNITY": "eer"},
    "werkuren_per_maand": {"2026-10": 40}, "inkomen_uit_arbeid": {"2026": 7200}, "inkomen_ouders": {"2026": 55000},
    "basisbeurs": {"2026-10": null}, "aanvullende_beurs": {"2026-10": null}
  }},
  "huishoudens": {"h": {
    "partners": ["ik"],
    "huur_per_maand": {"2026-10": 480},
    "zelfstandige_woonruimte": {"2026-10": false},
    "zorgtoeslag": {"2026-10": null},
    "huurtoeslag": {"2026-10": null}
  }}
}'
```

→ a German student at Maastricht University working 40 hours a month: `basisbeurs` 324.52,
`aanvullende_beurs` 338.09, `zorgtoeslag` 129, `huurtoeslag` 0 (a room is not self-contained).

## Project layout

```
openfisca_nl/              OpenFisca country package
  entities.py              persoon; huishouden (roles: partners = applicant + toeslagpartner, kinderen)
  enums.py, helpers.py     shared enums and the toeslagen rounding rule
  parameters/*.yaml        2025-2027 amounts, each with official references
  variables/*.py           inputs (invoer.py) and formulas per scheme
  tests/*.yaml             OpenFisca YAML tests
server.py                  Web API at /api + static questionnaire at /
web/                       Questionnaire: plain ES modules, no build step
  js/questions.js          the questions and when they are shown
  js/api.js                builds the OpenFisca situation; reads /api/variables so new outputs appear automatically
  js/benefits.js           result-card copy and official links
  js/app.js, js/i18n.js    UI and EN/NL strings
scripts/generate_api_doc.py  writes docs/api.md from the variables
docs/research/             sourced research notes for every amount and rule
```

## Privacy

Nothing is stored. The Web API is stateless: answers are sent once to calculate and are not saved by the app.
No accounts, no cookies, no trackers, no external fonts or CDNs.

## Keeping it up to date

Amounts are dated in the parameter files. OpenFisca keeps using the last known value, so add new dated values:

- every **1 January**: toeslagen, tax, DUO amounts, kindgebonden budget, Maastricht schemes;
- every **1 July**: bijstand norms, kinderbijslag, minimum wage;
- every **1 August / 1 September**: mbo lesgeld supplement, collegegeldkrediet.

Some 2027 values are already in (DUO, kindgebonden budget afbouwpercentage).

## Known simplifications

- Huurtoeslag: housemates other than partner and children (medebewoners) are not asked; their income would count.
- Studiefinanciering: current age instead of age at the start; two-parent households only (no single-parent or
  deceased-parent exemption, no €363 deduction for other children at home, no parents repaying their own debt).
- Migrant-worker status follows DUO's presumption; DUO assesses each case and checks payslips afterwards.
  Students who live in Germany or Belgium and work in NL are not modelled.
- Bijstand: kostendelersnorm, the 4-week search period for under-27s and the partner-specific rules are not modelled.
- Tax: box 1 only, below AOW age; box 3 and deductions are ignored; withholding is estimated by annualising
  the monthly wage.
- Maastricht schemes are indicators. The IIT's 36 months of low income, the studietoeslag's medical advice and the
  exact 2026 kwijtschelding asset norm cannot be checked by a questionnaire.
